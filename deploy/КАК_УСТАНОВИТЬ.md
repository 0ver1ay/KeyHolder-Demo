# Как установить KeyHolder на Linux Mint (простая инструкция)

Эта инструкция — для тех, кто не хочет разбираться в Docker, Python и прочем.
Просто **открывай терминал** и **копируй команды по порядку**.

> Подробная «взрослая» версия: [DEPLOY_MINT.md](DEPLOY_MINT.md)

---

## Что мы вообще делаем?

Представь, что у нас три части:

1. **База данных** — как тетрадь, куда записывается, кто взял какой ключ.  
   Она живёт в маленьком «ящике» Docker на этом же компьютере.

2. **Две программы с окошками:**
   - **AdminApp** — для администратора (настройки, пользователи).
   - **UserApp** — для обычного пользователя (взять/сдать ключ).

3. **Камера** (если есть) — делает фото, когда человек заходит в систему.

Всё это ставится **на компьютер с Linux Mint 22.2** (Zara).

---

## Что нужно заранее

- Компьютер с **Linux Mint 22.2**, обычный (не телефон).
- **Интернет** (чтобы скачать программы).
- Папка с проектом **KeyHolder** (например `~/KeyHolder`).
- Ты **залогинен** в обычный рабочий стол (не чёрное окно SSH без экрана).

### Как открыть терминал

Нажми **Ctrl+Alt+T** или найди в меню «Терминал».

### Как попасть в папку проекта

Подставь свой путь вместо примера:

```bash
cd ~/KeyHolder
```

Проверка: в папке должны быть файлы `main_admin.py`, `main_user.py` и папка `deploy`:

```bash
ls deploy
```

Если видишь список файлов — ты в правильном месте.

---

## ⚠️ Если `install_system_deps.sh` выдаёт ошибку

**Эти команды работают только на Linux Mint**, не на Windows.

### Ошибка `bad interpreter` или `$'\r': command not found`

Файл попал с Windows-переносами строк. Исправь **на Mint** (в папке проекта):

```bash
cd ~/KeyHolder
sed -i 's/\r$//' deploy/install_system_deps.sh
sed -i 's/\r$//' deploy/*.sh
sudo bash deploy/install_system_deps.sh
```

### Ошибка `No such file or directory` (папка KeyHolder)

Путь другой. Узнай, где лежит проект:

```bash
pwd
ls
```

Подставь свой путь, например:

```bash
cd /home/ivan/KeyHolder
# или
cd /home/ivan/Загрузки/KeyHolder
```

### Ошибка `Unable to locate package docker-compose-v2`

Обнови скрипт из репозитория (мы это уже поправили) или поставь Compose вручную:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin
docker compose version
```

### Ошибка `This script must be run as root`

Нужно именно **`sudo bash`**, не просто `bash`:

```bash
sudo bash deploy/install_system_deps.sh
```

## Шаг 0. Один раз: установить «всё нужное в системе»

Это скачает библиотеки для окошек, камеры и Docker.

**Важно:** замени `~/KeyHolder` на **свою** папку с проектом, если она лежит в другом месте.

```bash
cd ~/KeyHolder
sed -i 's/\r$//' deploy/*.sh
sudo bash deploy/install_system_deps.sh
```

Первая команда `sed` — на всякий случай, если проект копировали с Windows.

Попросит пароль — введи пароль от компьютера.

Потом **обязательно**:

```bash
sudo usermod -aG video $USER
```

И **выйди из учётной записи и зайди снова** (или перезагрузи компьютер).  
Без этого Docker и камера могут не заработать.

После входа проверь:

```bash
docker --version
```

Если видишь версию (например `Docker version 24...`) — хорошо.

## Шаг 1. Запустить базу данных

Скопируй настройки по умолчанию:

```bash
cd ~/KeyHolder
cp deploy/.env.example deploy/.env
```

Запусти базу:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
```

Если пишет **`POSTGRES_* variable is not set`** — не создан `deploy/.env`. Сначала:
`cp deploy/.env.example deploy/.env`

Подожди 10–20 секунд. Проверь:

```bash
docker compose -f deploy/docker-compose.yml ps
```

**Хорошо:** в колонке STATUS написано **healthy** (здоровый).  
**Плохо:** нет healthy — подожди ещё или смотри раздел «Если что-то не работает» внизу.

### Ошибка `failed to bind host port 127.0.0.1:5432/tcp`

Порт **5432 уже занят** на этом компьютере. Чаще всего — **PostgreSQL, установленный в системе** (не в Docker).

**1. Узнай, кто занял порт:**

```bash
sudo ss -tlnp | grep 5432
```

**2. Вариант А — освободить 5432** (если системный PostgreSQL не нужен):

```bash
sudo systemctl stop postgresql
sudo systemctl disable postgresql
docker compose -f deploy/docker-compose.yml up -d
```

**3. Вариант Б — оставить системный PostgreSQL, Docker на другом порту** (проще, если не уверен):

Открой `deploy/.env` и поменяй строку:

```
DB_PORT=5433
```

В `deploy/config.deploy.cfg` поменяй `port=5432` на `port=5433`.

Потом снова:

```bash
docker compose -f deploy/docker-compose.yml up -d
```

На шаге 3 копируй `config.deploy.cfg` как обычно — там уже будет порт **5433**.

**4. Если порт занят старым контейнером KeyHolder:**

```bash
docker compose -f deploy/docker-compose.yml down
docker compose -f deploy/docker-compose.yml up -d
```

## Шаг 2. Собрать две программы (AdminApp и UserApp)

Это займёт несколько минут. Нужен интернет.

**Важно:** на компьютере должен быть **весь проект**, не только папка `deploy/`.

Проверь перед сборкой:

```bash
cd ~/KeyHolder
ls requirements.txt main_admin.py main_user.py config.cfg views
```

Если `requirements.txt` **нет** — ты не в той папке или скопировал не весь проект. Нужны файлы из корня репозитория (`requirements.txt`, `main_*.py`, `views/`, `controllers/` и т.д.).

Скопировать с Windows на Mint можно так (с Windows, в PowerShell, подставь свой IP Mint):

```bash
scp -r ./KeyHolder-Demo user@YOUR_SERVER_IP:~/KeyHolder
```

Или на Mint через git:

```bash
cd ~
git clone https://github.com/0ver1ay/KeyHolder-Demo.git KeyHolder
cd KeyHolder
```

Сборка (займёт **10–20 минут**, не прерывай Ctrl+C):

```bash
cd ~/KeyHolder
bash deploy/build_linux.sh
```

Если в терминале сыпется `[TRACE]` на тысячи строк — это **не ошибка**, PyInstaller сканирует модули. В новом `build_linux.sh` вывод урезан. Просто жди, пока не появится `=== Build complete ===`.

### «Недопустимая инструкция» / `Illegal instruction` при `build_linux.sh`

Часто из‑за **numpy 2.x** на слабом или старом процессоре. Обнови проект и пересобери:

```bash
cd ~/KeyHolder
rm -rf .venv-build build dist
bash deploy/build_linux.sh
```

В новом `build_linux.sh` уже стоят пины для Linux (`numpy==1.26.4`, `pyinstaller==6.11.1`).

Если снова падает — пришли вывод:
```bash
cat /proc/cpuinfo | grep -m1 'model name'
python3 -c "import numpy; print(numpy.__version__)"
```

### Ошибка `SubprocessDiedError` / `collect_all('kivymd')` / exit code `-4`

PyInstaller падает при сборке KivyMD. Обнови проект (должны быть новые `deploy/pyinstaller/*.linux.spec`) и пересобери:

```bash
cd ~/KeyHolder
git pull   # или скопируй проект заново с Windows
bash deploy/build_linux.sh
```

Если снова падает — пришли новый лог.

### Ошибка «Could not open requirements file» / «не нашло requirements»

1. Убедись, что ты в **корне** проекта: `ls requirements.txt` должен показать файл.
2. Не запускай `pip install` из папки `deploy/` — только `bash deploy/build_linux.sh` из корня.
3. Если проекта нет целиком — скопируй или `git clone` всю папку `KeyHolder`, не одну `deploy/`.

В конце должно написать что-то вроде:

```
AdminApp: .../dist/AdminApp/AdminApp
UserApp:  .../dist/UserApp/UserApp
```

Проверь, что файлы есть:

```bash
ls -l dist/AdminApp/AdminApp
ls -l dist/UserApp/UserApp
```

---

## Шаг 3. Настроить подключение к базе

Скопируй готовый конфиг в обе программы:

```bash
cd ~/KeyHolder
cp deploy/config.deploy.cfg dist/AdminApp/config.cfg
cp deploy/config.deploy.cfg dist/UserApp/config.cfg
```

Этот файл говорит программам: «база на этом компьютере, порт 5433, логин postgres».

Если у тебя **другое оборудование** (шкаф с ключами по сети), открой `config.cfg` в блокноте и поменяй `device_host` и `device_port` — как в старом `config.cfg` на Windows.

---

## Шаг 4. Запустить программы

### Админка

```bash
cd ~/KeyHolder
bash deploy/run_admin.sh
```

Должно открыться **окно** программы.

Первый раз можно войти как **admin** / **admin** (если ещё не меняли).

### Пользовательское приложение

В **другом** терминале (или закрой админку и запусти):

```bash
cd ~/KeyHolder
bash deploy/run_user.sh
```

Тоже должно открыться окно.

## Как понять, что всё работает?

Поставь галочки:

- [ ] База: `docker compose -f deploy/docker-compose.yml ps` → **healthy**
- [ ] AdminApp открылось **без красных ошибок** в терминале
- [ ] UserApp открылось **без красных ошибок**
- [ ] В терминале есть строка **`[DB] Connected`** — значит программа нашла базу
- [ ] Можно зайти в программу и увидеть интерфейс (кнопки, экраны)

Если всё так — **установка удалась**.

## Про камеру (простыми словами)

Камера нужна **не для входа в программу**, а чтобы **делать фото** при работе пользователя.

Чтобы камера работала:

1. Камера подключена к компьютеру.
2. Ты сделал шаг 0 с `usermod -aG video` и **перезашёл** в систему.
3. В `dist/UserApp/config.cfg` (и AdminApp, если нужно) стоит `camera_index=0` — это первая камера.

Проверка, видит ли компьютер камеру:

```bash
ls -l /dev/video0
```

Если файл есть — камера на месте.

При запуске смотри в терминал:

- **Хорошо:** `CameraService: started`
- **Плохо:** `CameraService: start() failed` — программа **всё равно работает**, просто **без фото**

Если камера не нужна — можно не трогать, ключи и база будут работать.

## Если что-то не работает

### «Не могу найти docker»

Сделай шаг 0 заново, **выйди и зайди** в систему.

### «Окно программы не открывается»

Запускай **с рабочего стола Mint**, не из SSH без экрана.  
Сделай шаг 0 ещё раз:

```bash
sudo bash deploy/install_system_deps.sh
```

### `failed to bind host port 127.0.0.1:5432/tcp`

См. подробно в **шаге 1** выше. Кратко: порт 5432 занят → останови `postgresql` в системе **или** поставь `DB_PORT=5433` в `deploy/.env` и `port=5433` в `deploy/config.deploy.cfg`.

### «База не подключается»

```bash
docker compose -f deploy/docker-compose.yml ps
```

Должно быть **healthy**. Если нет:

```bash
docker compose -f deploy/docker-compose.yml up -d
```

Проверь, что ты скопировал конфиг (шаг 3).

### «Не нашло requirements» / `requirements.txt`

Сборка ищет файл в **корне** проекта (`~/KeyHolder/requirements.txt`).

```bash
cd ~/KeyHolder
ls -l requirements.txt
```

Нет файла → скопируй **весь** проект с Windows или сделай `git clone`. См. шаг 2.

### «AdminApp binary not found»

Сначала собери программы (шаг 2):

```bash
bash deploy/build_linux.sh
```

### «Камера не работает»

- Перезайди в систему после `usermod -aG video`
- Проверь `ls -l /dev/video0`
- Попробуй другой номер в config: `camera_index=1` вместо `0`

Программа без камеры **не сломана** — просто не будет фотографий.

### Всё сломалось и хочешь начать базу с нуля

**Внимание: удалит все данные в базе!**

```bash
docker compose -f deploy/docker-compose.yml down -v
docker compose -f deploy/docker-compose.yml up -d
```

Потом снова запусти программу — она создаст пустые таблицы заново.

## Шпаргалка: что за что отвечает

| Файл / папка | Зачем |
|--------------|--------|
| `deploy/install_system_deps.sh` | Один раз ставит всё в систему |
| `deploy/docker-compose.yml` | Запускает базу данных |
| `deploy/build_linux.sh` | Собирает AdminApp и UserApp |
| `deploy/config.deploy.cfg` | Настройки для базы на этом ПК |
| `deploy/run_admin.sh` | Запуск админки |
| `deploy/run_user.sh` | Запуск пользовательской программы |
| `dist/AdminApp/` | Готовая админка |
| `dist/UserApp/` | Готовая пользовательская программа |

## Порядок команд целиком (копируй блоками)

```bash
# 0. Один раз + перезаход в систему
cd ~/KeyHolder
sed -i 's/\r$//' deploy/*.sh
sudo bash deploy/install_system_deps.sh
sudo usermod -aG video $USER
# → выйти из учётки и войти снова

# 1. База
cd ~/KeyHolder
cp deploy/.env.example deploy/.env
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml ps

# 2. Сборка
bash deploy/build_linux.sh

# 3. Конфиг
cp deploy/config.deploy.cfg dist/AdminApp/config.cfg
cp deploy/config.deploy.cfg dist/UserApp/config.cfg

# 4. Запуск
bash deploy/run_admin.sh
# в другом терминале:
bash deploy/run_user.sh
```

Готово.
