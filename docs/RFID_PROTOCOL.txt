RFID TCP протокол (кратко)

Формат сообщений (строка UTF‑8, одна на соединение):
- USER:<rfid_code>  — RFID пользователя (общий считыватель)
- KEY:<rfid_code>   — RFID ключа (общий считыватель, один на устройство)
- LOCK:OPEN         — общий замок шкафа открыт (начать окно опроса слотов)
- LOCK:CLOSE        — общий замок шкафа закрыт (завершить окно опроса слотов)

Сервер: `services/rfid_server.py`
Эмулятор: `scripts/rfid_simulator.py` (есть кнопка «Открыть общий замок»)
Эмулятор без железа: `python scripts/rfid_simulator.py`.

Сдача ключа (return)
- Пользователь **авторизован** и находится на экране «Сдать ключ».
- Достаточно приложить ключ к **общему** RFID-считывателю → `KEY:<rfid>` (popup и клик по плитке не нужны).
- С главного меню `KEY:` **не** инициирует сдачу.
- Секретный код (гостевой экран): после ввода кода — `KEY:<rfid>` на общем считывателе.

Выдача ключа (issue)
- После `KEY:<rfid>` с общего считывателя (или по клику на плитку) открывается ячейка ключа.

Опрос ячеек (слотов) — legacy / общий замок
- Абстракция: `services/slot_poller.py` — `SlotRfidPoller(provider, interval_sec)` с колбэком `set_on_presence_change(cb)`.
  - Провайдер возвращает снимок `{(x, y): present_bool}` для текущего бокса.
  - Мок‑реализация: `MockSlotRfidPoller` на таймере Kivy `Clock`, сравнивает снимки и вызывает колбэк только при изменениях.
- Интеграция: контроллер запускает опрос в `handle_lock_open()` и останавливает по таймауту окна/закрытию замка.

Маппинг слотов на ключи
- Используем `keys.box_id`, `keys.pos_x`, `keys.pos_y` для связи «слот → Key».
- Если у каждого места будет уникальный RFID считыватель, можно добавить поле `keys.slot_rfid` (пока не требуется, логика готова к расширению).

Фиксация взятия/сдачи по слотам
- Детекция: `present → absent` = взятие, `absent → present` = сдача.
- Реализация (мок): присутствие считается истинным, если по ключу нет записи в `issued_keys`.
- При изменении:
  - Взятие: создаётся запись в `issued_keys`, добавляется `events(action='issue')`, обновляется `user_keys.state/state_user_id/state_updated_at`.
  - Сдача: удаляется запись из `issued_keys`, добавляется `events(action='return')`, обновляется `user_keys.*`.
- Контекст: используется текущий авторизованный пользователь (`_current_user`). Для `admin` выдача не производится.

UX и сценарии
- Замок открывается, как только пользователь заходит в сценарий «взять» или «сдать» (временная имитация; далее — Modbus).
- В окне «взять/сдать» опрос активен ограниченное время, затем останавливается и индикатор скрывается.
